# IQVideo 双教室互动控制台

首次接手请读 [AI 交接手册](./AI_HANDOFF.md)，其中包含客户目标、家用电脑的离线启动步骤、代码入口和实机验收边界。

同一台 Windows 实验室电脑可控制三楼和一楼的 LCS810，查看真实互动视频和两台录播上的录像。首页和录像库支持简体中文、英文、法文。给客户演示时可共享本机浏览器窗口。

## 在 Windows 上启动

在 PowerShell 中运行以下命令。首次安装依赖需要网络，此后启动和演示无需联网。

```powershell
Set-Location -LiteralPath 'D:\Github\IQ\mockup_generator\apps\lcs-unified-browser'
.\start.cmd --setup
.\start.cmd
```

`--setup` 使用 `%USERPROFILE%\MiniConda3\python.exe` 创建项目内的虚拟环境。如果 Miniconda 装在其他目录，可以先将 `LCS_DEMO_PYTHON` 环境变量设为可用的 Python 3.11 或更高版本的绝对路径。启动后保持命令窗口打开。双击 `end.cmd` 或在另一个终端执行 `.\end.cmd` 可关闭本机网页服务，也可在启动窗口按 Ctrl+C。要结束设备上的互动，请在关闭服务前点击网页的「结束课堂」。

- 本机打开[互动控制台](http://127.0.0.1:8088/)，也可直达[中文真机](http://127.0.0.1:8088/?mode=live&lang=zh)、[法文真机](http://127.0.0.1:8088/?mode=live&lang=fr)或[双路录像库](http://127.0.0.1:8088/?mode=live&lang=zh#library)。
- 首页默认选中排在首位的「真机」。打开页面只读取状态，点击开课才发起互动。在家可直接打开[离线演示](http://127.0.0.1:8088/?mode=demo)。
- 真机课堂控制使用本机地址。原有只读录像页仍可从同一内网的 `http://实验室电脑IP:8088/library` 访问。
- 本地导播和互动预览使用厂家播放器。录播的 HTTPS 管理端口、9898 预览端口、TCP 6558、录像 HTTP 9090 及设备返回的 RTSP 端口需从实验室电脑可达。OUT 接收预览调用 PATH 中的 FFmpeg；本机已配置。

## 互动课堂

真机离线时，教室控制区提供「请求开机」。厂家协议规定 `0x3105` 的 `power=2` 为开机，本控制台走录播本地 TCP 6558。按楼层独立发送一次。等待期间该楼按钮置灰，服务端每 10 秒读取设备状态，刷新页面也能继续查看。连接失败且命令未发出时，复查后可重试。关机参数为 0，重启为 1，开机按钮始终发送 2。待机时该端口是否可达仍需在本批设备上实测。集控 TCP 8863 另有设备注册和关机心跳流程。本地对接资料中未找到标准 Wake-on-LAN 魔术包的定义。设备完全断电时需先恢复供电。[厂家协议 · 电源管理](https://github.com/ToastmastersLee/QNEX/blob/main/Q-NEX_PRD/Q-NEX_API/LCS-API/LCS810-API-%282%29%E5%BD%95%E6%92%AD%E6%8E%A5%E5%8F%A3%281-15%29.md)

1. 在「课堂」选择主讲楼层并开课。已有课堂可读取并接续；若只有听课端离开，可单独重新加入。机身在文件回放页时固件可能返回 `uvc occupied`，先在该机退出回放，再重试加入。
2. 在听课端的 OUT1、OUT2 卡上独立选源。三楼当前有效课件输入为「电脑2」。每张卡上的通道是设备回读值，预览时间随真实视频帧更新。一楼 OUT1 接左屏，OUT2 接右屏。反向课堂读取三楼接收布局；三楼两个实体插口的接线位置待现场核对。
3. 可监看任一楼层的本地导播 PGM 或原生互动预览。OUT 卡显示设备分配至该目标的全屏接收流。实体屏上的文件列表、导播菜单和 IFP 自身的叠加层需在现场核对。
4. 在「设置」按楼层暂存默认源、清晰度、双屏、默认开麦数、发言方全屏等改动，再点「应用并重开」。网页显示已有录像及操作影响，一次结束课堂、回读配置并重建连接。若一端暂时不可用，按页面提示修复后可重试已暂存的改动。
5. 在主讲端授权或收回听课端发言，也可分别控制录制。验证声音触发时，打开「发言方全屏」并让已开麦的听课端直接讲话；再测试老师点名。记录实际看到的主讲端画面。只有一个远端教室时，单靠已经全屏的画面不能判断声音触发。
6. 录像库按设备及课程目录组织文件。打开同一堂课的 `Lecture2.mp4` 和 `Teacher_C.mp4` 可用网页联动播放、暂停和跳转，单选一路声音。录像继续存于各自的录播；机身的 HDMI 文件回放采用它自己的播放器。

## Q-NEX 直播分发

在「直播分发」选择 Lee 或 Codex、录播来源及接收设备，确认分发音量后点「推送到所选设备」。已有推流可选择「使用直播间当前流」，支持纯音频。需要授权时在当前页输入 Q-NEX 账号，登录成功会接着执行原操作。密码仅用于本次登录，会话令牌保存在本机服务内存中。

控制台通过录播 API 读取所选通道的地址和开播状态。通道已配置到目标房间或录播本机 RTMP 时，可自动开启该通道。本机 RTMP 或已开启的 RTSP 源由 FFmpeg 原样转发，录播直推目标房间时直接验证回放。服务通过 Q-NEX Console 的 HTTPS 接口下发并回读状态。运行期间保持本机服务开启。点击「结束本次分发」会停止此次分发、释放转发，并关闭本次自动开启且已无人使用的录播通道。需要实验室网络及 PATH 中的 ffmpeg 和 ffprobe。教室实际音量需在接收端确认。

## 配置真机

编辑本目录的 `config.local.json`，保存后重启服务。没有这个文件时，服务使用空白模板。可复制 `config.example.json` 为 `config.local.json` 再填写房间、IP 和端口。当前本机已填写如下配置：

| 设备 | 房间 | IP | 设备 TCP | 录像 HTTP |
|---|---|---|---:|---:|
| A | 三楼 | `192.168.3.50` | 6558 | 9090 |
| B | 一楼 | `192.168.1.80` | 6558 | 9090 |

浏览器内点「真机」开始查询。若有一台 IP 留空，该设备会显示不可用。录像库可手动刷新，常规查询复用最多 60 秒的目录。

当前两台的 TCP 读取和 HTTP 9090 录像服务可按厂家协议直接读取。设备原生管理网页仍使用自己的登录流程。如果设备配置为对录像服务使用 HTTP Basic 或 Digest 认证，在对应设备的本机配置项填写 `auth`（`basic` 或 `digest`）、`username`、`password`。本机配置已被 Git 忽略。若录像服务采用其他认证方式，页面会显示访问失败。请在可访问这些录像的内部网络上运行此服务。

## 原有录像浏览功能验收

### 2026-11-19 互动控制台实测

在同一台实验室电脑的 Edge 中，三楼和一楼的 PGM 与原生互动预览均能连续解码。一楼接收端的 OUT1 和 OUT2 在同一窗口实际解码出两幅不同的 640×360 监看画面。三楼主讲时完成五次独立切源，包含左课件／右教师特写、单换学生全景和左右对调。一楼主讲时也取得三楼两路接收分配并分别切源。

控制台一次执行了换主讲、保存多项设置和重新加入。设为默认开麦 4 后，一间听课教室自动解除静音；两种角色均已建立课堂。主讲端可以授权和收回听课端的发言。仅一间听课教室时，设备在授权发言前就可能把该教室作为全屏主画面。默认开麦、授予发言、实际讲话自动触发全屏是三项不同的验收结果。录制控制在一楼完成开始、暂停、继续和停止的真机回读。

从一楼 2026-11-16 17:24:51 的课程打开课件和教师特写，两路均解码为 1920×1080。联动跳到 00:30 再播放，抽查读数为 31.030 和 31.021 秒。本次为短时网页播放验收，整堂课同步与实体双 HDMI 文件回放仍需分别验证。

### 只读录像页复测步骤

1. 用「演示数据」检查两张卡。搜索 `Lecture.mp4` 应保留两个来源的同名条目。加房间和日期条件后应只返回符合条件的条目。点「清空」恢复全部，未填课程和教师显示「未标注」。
2. 播放一段演示录像，确认画面、声音和拖动进度。切到「真机」后，检查播放器已停止并清空。
3. 核对两台卡片上的录制状态和容量。卡片使用 `0x3106` 的原始 MB 数值，已用量等于总量减剩余量。设备原生页面若使用 GB，按其显示换算后比较。
4. 搜索 `Lecture.mp4`，确认两台都有结果。按一楼、三楼及录像日期分别缩小结果，再在各自来源选一段录像，确认画面和声音，拖动到中段后应继续播放。
5. 在单独的测试配置中将一台 IP 换成不可达地址，重启测试服务。确认故障设备显示离线，健康设备仍可检索和播放。恢复配置后刷新复查两台状态。

如果设备卡显示离线，检查服务电脑能否访问对应 IP 和 TCP 6558。如果列表不完整，保留页面显示的来源与错误并重试。播放失败时检查来源设备的 HTTP 9090 和浏览器支持的编码。不同通道可能采用不同编码，建议用 Edge 或 Chrome 测试 H.264/AAC 录像。

## 接口与测试

- 录像目录与回放依据 `LCS810-API-(1)`、`(2)` 第 1 节和 `(4)` 第 54、55、58、60 节。读取命令为 `0x3106`、`0x3149`、`0x3153`。
- 互动控制复用本固件 HTTPS 管理服务的课堂、发言和设置命令。双流切换使用本地 TCP 的 `0x4409/0x440B`，设备配置、接收布局和取流分别用 `0x4412`、`0x4403`、`0x4414` 核对。当前测试固件为 `8.1.702-release-ss528v100`，其他固件的原生播放器需核对版本。
- 录像以设备、目录和文件名识别。搜索查看两台设备的结果，视频代理只接受结果中的录像 ID。Range 请求转到已配置的来源设备。
- 运行 `.\.venv\Scripts\python.exe -m unittest discover -s tests -v` 可复测协议和媒体转发。
